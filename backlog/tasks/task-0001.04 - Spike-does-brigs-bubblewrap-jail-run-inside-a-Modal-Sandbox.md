## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Probe written: modal run -m bh02_lab.modal_apps.rollout::probe runs bh-02 jailed in a Modal Sandbox on bh-02's fake model and returns the jail status line and bh-02's log. Locally (Docker-less container, bubblewrap from apt) bh-02's jail comes up: 'jailed fs_write ✓ network ✓ fs_read ~ env ✓'. Modal sandboxes run on gVisor; Sandbox.create also takes runtime='vm' if gVisor refuses user namespaces. Awaiting the Modal run.

First probe on Modal (2026-10-25, gVisor runtime): bh-02 started and planned 'jailed fs_write ✓ network ✓ fs_read ~ env ✓', but brig's supervisor failed: 'bwrap: loopback: Failed RTM_NEWADDR: No such file or directory'. gVisor's netstack won't let bubblewrap configure loopback in a new network namespace, so bh-02's own jail can't start under gVisor. The run also showed the runner would have scored that as the model crashing; prepare now smoke-runs bh-02 on its fake model in the same jail first, so a jail that can't start is the lab's failure. Next: probe --runtime vm (bh-02's jail on Modal's VM runtime), and probe --jail sandbox (no jail, a PID namespace via unshare, on gVisor).

Second probe (gVisor, --jail sandbox): bh-02 ran unjailed and replied, but isolated was false: unshare could not make a PID namespace under gVisor, so a process the model started could outlive bh-02. Fixed: without a jail, the runner now passes --agent-uid 1000; bh-02 runs as an unprivileged 'agent' user (setpriv), and every process of that user is killed when bh-02 exits. bh-02's Python is installed under /opt/uv-python so the agent can run it. Proven locally: tests/e2e (BH02_AGENT_CHECKOUT) shows the model's code ran as uid 1000 and a process it started in a new session was gone before it could write. Still to run: probe --runtime vm.

Third probe (gVisor, --jail sandbox, at 6f4a59f): bh-02 replied, the model's code ran as uid 1000, isolated true. pins.toml set to jail = "sandbox" on gvisor so the lab can go on. The --runtime vm probe's output was not seen yet; if it shows bh-02's own jail starting (failed null, ended replied), switch to runtime = "vm", jail = "bh-02", which also keeps the inference key from the model's code.
