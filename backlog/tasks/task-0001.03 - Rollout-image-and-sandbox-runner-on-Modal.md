## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The image is bh-02 at the pinned SHA plus the headless driver, named by digest. The runner starts a single-use Modal Sandbox per RolloutRequest with no Modal, Claude or Hugging Face credential, runs the task and returns the snapshot and transcript into the lab volume by content hash.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The runner refuses a request whose image digest is not the built one
- [ ] #2 The sandbox holds only the inference key, and no other secret
- [ ] #3 Snapshot and transcript land in the volume under their content hashes
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
### Order of work
1. Create the bh02-lab-inference secret. 2. Deploy serve, then rollout. 3. modal run probe_jail (TASK-0001.04). 4. Call rollout.image_digest twice and check the same digest comes back. 5. Run one rollout of paginate by hand and read its events and log in the artefacts volume.
### Risks
The image defined again inside a container must be the same image (same files, shipped under /lab/repo); if the digests differ every request is refused, which is safe but stops the lab. Reading a large work.tar back through the sandbox filesystem may hit a size limit (the sandbox already leaves caches and environments out).
### Proof
A Rollout JSON with ended replied or budget, and its snapshot in bh02-lab-artefacts.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Built: src/bh02_lab/modal_apps/rollout.py (rollout image from the pinned SHA plus headless row plus sandbox program; the runner refuses another image digest or serving hash; the key goes in as a file the program removes; outbound traffic limited to the serving host), src/bh02_lab/sandbox/entry.py, src/bh02_lab/rollout_core.py (the lab's failures raise; endings whitelisted; oversized workspaces are the model's). Evidence so far is local: tests/e2e/test_sandbox_entry.py runs entry.py against the real bh-02 and proves the key reaches a stub OpenAI server while the jailed model's read of local.env fails. Not yet run on Modal: needs the deploy steps in README.

Second review round: the runner now runs the sandbox program in two commands, prepare (lab) and run (model), with a serving health check before and after (rollout_core.lab_failure); everything after bh-02 starts counts against the model (rollout_core.settled never raises), so a deep tree, a full disk, a huge file or a killed program is a fail, not an exclusion. Packing walks the workspace without recursion under the snapshot's caps (64 MB, 5000 files, depth 64) and writes 'oversized' itself; disk is set aside in prepare and freed before outputs are written; the runner checks the tar's size before reading it. Without bh-02's jail, bh-02 runs in its own PID namespace (unshare) when the sandbox allows, replacing the process killing that could have hit Modal's helpers. Evidence: tests/unit/test_rollout_core.py, tests/unit/test_entry_skips.py, tests/e2e/test_sandbox_entry.py (including a process started in a new session that is gone when bh-02 ends).
